# Authorized fetch audit

This audit covers origin fetch sites outside the extracted publish manifest and carry refresh. Line numbers refer to the current implementation and may move.

| Path and line | Command and purpose | Authentication and grant behavior | Redaction | Failure handling | Separate follow-up candidate |

No credential-helper override is added to the fetch command. | No token redaction in fetch detail. | Returns JSON `step=fetch` on nonzero exit; boundary event only when grant opened. ## Proposed follow-up issue scopes

- Review `publish_ops.py` base-ref fetches against #933 manifest prefetch. Confirm all call paths and retain branch fallback semantics before removing or consolidating either fetch.
- Define an explicit authentication and error contract for `merge_base.py` refspec fetch; the current grant-only-proxy policy and absent credential helper differ from #940.
- Review clone plus PR-head checkout as one lifecycle, since one read grant currently spans both operations.
- Decide whether `git_fetch_origin` callers such as diff should remain best-effort native fetches or require host-authorized access for token-free private repositories.
